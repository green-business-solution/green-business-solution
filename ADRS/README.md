# Architecture Decision Records

Use this folder for decisions that future agents should understand before changing the same area.
ADRs should be short, dated, and specific.

Prefer adding an ADR when a change affects architecture, deployment shape, data ownership, security boundaries, workflow policy, or long-term maintainability.
Do not use ADRs as a running changelog.

## Format

Each ADR should include:

- Status.
- Date.
- Context.
- Decision.
- Alternatives considered.
- Consequences.
- Follow-up.

Use names like `0001-adopt-ai-workflow.md`.
